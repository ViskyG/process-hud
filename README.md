# Process HUD

**Codex не должен тратить квоту на ожидание процессов.**

Сборка проекта, тесты, импорт данных или загрузка могут выполняться минутами и часами. Сама работа идёт без участия ИИ, но Codex нередко продолжает спрашивать у системы: «Ещё работает? А теперь? А теперь?» Такие проверки расходуют модельные ходы и контекст, хотя ничего не меняют.

**Process HUD передаёт ожидание обычной локальной программе.** Codex регистрирует длительную задачу, получает её идентификатор и заканчивает свой ход. Пока команда выполняется, HUD следит за ней без обращений к модели. Когда процесс завершится — успешно, с ошибкой или прерыванием — подключённый мост сообщит результат в исходный диалог, чтобы Codex мог продолжить работу. Если во время выполнения возникла ситуация, требующая решения, HUD может сообщить и об этом.

Это главная задача проекта. Полупрозрачная панель — удобный способ видеть происходящее самому, не возвращая агента к работе ради очередной проверки.

## Вместо постоянных проверок — одно событие

Обычный подход выглядит так:

```text
Codex запускает тесты
  → проверяет, закончились ли они
  → ждёт
  → снова проверяет
  → ждёт
  → снова проверяет
  → наконец читает результат
```

С Process HUD:

```text
Codex запускает тесты через HUD
  → HUD принимает наблюдение за процессом
  → Codex завершает ход и не расходует токены на ожидание
  → HUD самостоятельно отслеживает выполнение
  → готов результат или нужна помощь? HUD отправляет событие
  → Codex возобновляет работу в нужном диалоге
```

HUD не «думает» вместо агента и не вызывает модель каждую секунду. Он проверяет состояние процесса обычными средствами операционной системы. Модель снова нужна лишь тогда, когда появился результат или действительно требуется её решение.

При этом Codex получает не только сообщение об успехе: **ошибка, прерывание и потеря возможности достоверно определить результат тоже обрабатываются**. Неизвестный исход не выдаётся за успешный, а задача не запускается повторно самовольно.

### Почему это важно для квот

В [исследовании JetBrains Benjamin-Plus](https://github.com/JetBrains/benjamin-plus-skill/blob/main/EXPECTED-RESULTS.md) на Java SWE-bench **45,8% шагов агента в одной из изученных конфигураций были проверками состояния**, включая 3 982 опроса с интервалом менее пяти секунд. Это не означает «45,8% всех токенов»: измерялась доля шагов конкретной конфигурации. Но масштаб бессмысленной работы хорошо виден.

Мы проверили и собственно ожидание через Process HUD. В двух испытаниях — обычного диалога Codex и цепочки «субагент → основной агент» — за **120 секунд ожидания было 0 новых модельных ходов и 0 обновлений счётчиков токенов**. После выполнения результат дошёл до нужного диалога. Отдельно проверялись доставка успешного завершения, ошибки и прерывания.

То есть **наблюдение за длительной задачей можно выполнять вообще без модельных вызовов в период ожидания**. Это не обещание фиксированного процента экономии всей квоты: запуск задачи, обработка результата и последующая работа агента по-прежнему расходуют токены.

## Как Codex работает с HUD

Для агента предусмотрен **skill** — инструкция, которая учит использовать Process HUD по назначению:

- передавать HUD достаточно долгие неинтерактивные команды, а не все подряд;
- после регистрации задачи прекращать собственные циклические проверки и ожидание через `sleep`;
- возвращаться к задаче по событию о завершении, ошибке или необходимости вмешательства;
- читать итоговый отчёт, проверять результат и убирать обработанную запись из панели.

Например, когда подключён мост автоматического продолжения, Codex может запустить:

```bash
process-hud run --title "Тесты проекта" --resume-codex --cwd /путь/к/проекту -- python3 -m pytest
```

HUD запоминает, какой диалог запустил задачу. В случае работы субагента результат направляется основному агенту. Так ожидание не требует ни постоянно активного диалога, ни отдельного модельного хода для пересылки результата от уже завершившего работу субагента.

**Skill доступен Codex в VS Code и терминальном Codex.** Самостоятельное наблюдение за задачами через HUD работает и без моста. Для **автоматического возобновления исходного диалога** нужна отдельная интеграция с клиентом Codex: в текущей опубликованной установке предусмотрен мост для Codex в VS Code на Linux x86_64. Он описан ниже; отдельного установщика такого моста для терминального интерфейса в репозитории пока нет.

## Установка

Сейчас Process HUD рассчитан на **Linux**; графический интерфейс проверен на Ubuntu 24.04 с GNOME/X11. Нужны Python 3.10+, `venv` (на Ubuntu — `python3-venv`) и интернет для установки зависимостей.

```bash
git clone https://github.com/ViskyG/process-hud.git
cd process-hud
bash install.sh
```

Установщик создаст отдельное Python-окружение, команду `process-hud` и установит skill в `~/.agents/skills/process-hud`. Автозапуск не включается.

Покажите панель:

```bash
~/.local/bin/process-hud ui show
```

Проверьте её на настоящей демонстрационной задаче:

```bash
~/.local/bin/process-hud run --title "Демонстрация" -- \
  ~/.local/share/process-hud/venv/bin/python \
  ~/.local/share/process-hud/examples/demo.py
```

Команда сразу вернёт идентификатор задачи, а в панели появится её ход выполнения. После завершения можно нажать на строку и посмотреть логи и результат.

## Подключение автоматического продолжения Codex

Если вы используете **Codex в VS Code**, из каталога репозитория выполните:

```bash
~/.local/share/process-hud/venv/bin/python scripts/install_codex_bridge.py
```

Затем один раз перезагрузите окно VS Code. Мост подключается к существующему Codex App Server, передаёт события в исходный диалог и позволяет агенту начать новый ход после завершения фоновой задачи. Настройки VS Code предварительно сохраняются в резервную копию.

Интеграция **не включается основной установкой**: это отдельное действие. Когда мост не подключён, HUD продолжает показывать и сохранять результаты задач, но не может автоматически возобновить диалог Codex.

## Что ещё умеет Process HUD

Программа полезна и без Codex:

- **Небольшая прозрачная панель поверх окон.** Видно, какие задачи ещё работают, а какие завершились; окно подстраивается под список.
- **Логи и результат по клику.** Можно посмотреть код завершения и последние сообщения программы.
- **Реальный прогресс.** Если задача сообщает число обработанных элементов или проценты, HUD показывает прогресс и оценивает оставшееся время. Если таких данных нет — не придумывает их.
- **Несколько источников задач.** Локальные процессы, подключение к существующему PID, Docker, Kubernetes Job и SSH.
- **Уведомления и звук.** О завершении можно узнать, даже если панель не на виду.

В GNOME панель открывается через **Ctrl+Alt+H**, если сочетание свободно. Нажатие на крестик рядом с задачей **убирает её из панели, но не останавливает процесс**. `Ctrl+Z` в окне HUD возвращает запись в текущем сеансе.

## Границы работы

Process HUD не управляет остановкой или перезапуском процессов и не гарантирует, что они переживут выход из системы или перезагрузку. Сбой связи сам по себе не считается ошибкой задачи. Для реального прогресса нужна информация от программы; проценты не вычисляются по загрузке процессора.

Проверены Linux/GNOME/X11, локальные задачи, подключение к Docker и автоматическое возобновление Codex через описанный мост, включая ошибки и прерывания. Реальные Kubernetes Job и удалённый запуск по SSH в опубликованном отчёте не значатся среди проведённых живых испытаний. Windows, macOS и полноценное поведение поверх окон в Wayland не проверены.

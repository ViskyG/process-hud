# 👀 Process HUD

**Фоновые задачи — под присмотром. Токены — для работы.**

Небольшая прозрачная панель поверх окон: сборки, тесты, импорты и загрузки видны
одним взглядом. HUD следит за ними локально, без запросов к модели во время ожидания.
С дополнительным мостом Codex получает событие и продолжает тот же диалог.

![Process HUD: прозрачная панель с задачами](docs/images/process-hud.png)

*Настоящий интерфейс Qt, демонстрационные данные.*

**Сейчас: Linux.** Проверено на Ubuntu 24.04, GNOME/X11. macOS и Windows пока
не поддерживаются; на Wayland положение поверх окон не гарантировано.

## Что умеет

| Возможность | Зачем это удобно |
| --- | --- |
| Прозрачная панель поверх окон | Видны название, состояние, измеренный прогресс и оценка оставшегося времени |
| Отдельное окно подробностей | Логи и код выхода доступны кликом по строке |
| Запуск и подключение к PID | Можно наблюдать новую или уже работающую задачу |
| Docker, Kubernetes Job, SSH | Есть адаптеры для существующего окружения и доступа |
| Уведомления и звук | Завершение заметно, даже когда вы заняты другим |
| Codex Skill и необязательный мост | Агент отдаёт ожидание HUD, получает результат и убирает обработанную строку |

Панель сама подстраивает высоту и работает на нескольких мониторах.
**Крестик убирает строку, процесс продолжает работать.** Ctrl+Z в HUD возвращает её.

## Зачем экономить на «ну как там?»

Частые проверки статуса могут занимать заметную часть работы агента.
В [анализе JetBrains](https://github.com/JetBrains/benjamin-plus-skill/blob/main/EXPECTED-RESULTS.md)
на Java SWE-bench опросы составили **45,8% шагов одной из исследованных конфигураций**.
Это доля шагов; универсальный процент расхода квоты из неё не следует.

Process HUD передаёт такое ожидание обычной локальной программе. Для типичных
фоновых команд агенту достаточно запустить задачу и вернуться по событию.
В наших двухминутных проверках у ожидающих диалогов было **0 новых модельных ходов**.
[Источники и границы измерений →](docs/RESEARCH.md)

## Установить

Нужны **Python 3.10+**, модуль `venv` и интернет для установки зависимостей.
Клонируйте репозиторий или скачайте и распакуйте ZIP с исходниками:

```bash
git clone https://github.com/ViskyG/process-hud.git
cd process-hud
bash install.sh
~/.local/bin/process-hud ui show
```

Для ZIP достаточно выполнить последние две команды в распакованной папке.

Установщик создаст отдельное окружение и добавит skill в `~/.agents/skills/process-hud`.
Предыдущий одноимённый skill сохранится в резервной копии. Автозапуск не включается.

Проверим первую задачу:

```bash
~/.local/bin/process-hud run --title "Первая задача" -- \
  ~/.local/share/process-hud/venv/bin/python \
  ~/.local/share/process-hud/examples/demo.py
```

## Подключить к Codex

Skill уже установлен. Можно написать агенту:

> Используй $process-hud для долгих фоновых команд. По результату продолжай работу
> и убирай из HUD строки, которые уже обработал.

Для автоматического возвращения в диалог включите **экспериментальный мост для
Codex в VS Code**. Из папки репозитория:

```bash
~/.local/share/process-hud/venv/bin/python scripts/install_codex_bridge.py
```

Перезагрузите нужное окно VS Code один раз. Теперь агент может запускать выбранные
задачи с `--resume-codex`. При завершении, ошибке или событии «нужно внимание»
результат приходит владельцу диалога; задачи субагентов возвращаются родителю.
Обычные короткие команды остаются в обычном рабочем потоке.
[Как устроен мост и как его отключить →](docs/CODEX_BRIDGE.md)

## Под рукой

| Действие | Как |
| --- | --- |
| Показать панель | **Ctrl+Alt+H** в GNOME или `process-hud ui show` |
| Открыть подробности | Клик по строке |
| Убрать строку / вернуть | Крестик / **Ctrl+Z** при фокусе в HUD |
| Скрыть панель | Escape или крестик панели |
| Прочитать результат | `process-hud report ID` |

Если команда не находится, используйте `~/.local/bin/process-hud`.
Прогресс появляется по реальным данным задачи. Тишина в логах не считается зависанием.

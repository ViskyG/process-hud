# Установить Process HUD и подключить к Codex

**Этот документ можно передать любому агенту Codex или открыть из skill при первом использовании HUD.** Установка HUD — общая для одного пользователя Linux, а не персональная для агента или проекта. После установки одной и той же командой, skill и панелью могут пользоваться другие экземпляры Codex в этом окружении. Повторная установка каждым агентом не требуется. Цель — настроить работу, при которой Codex передаёт длительные неинтерактивные команды Process HUD, завершает ожидающий ход и получает событие после успеха, ошибки или ситуации, требующей внимания. В период ожидания агент **не должен сам опрашивать процесс**.

## Инструкция для агента Codex

Пользователь поручил установить и подключить Process HUD на своей машине. Выполняй следующие шаги последовательно; не выдавай запуск процесса за его успешное завершение. Не устанавливай компоненты от root и не меняй файлы вне пользовательского профиля без отдельного согласования.

### 1. Найди исходники и проверь окружение

Репозиторий: `https://github.com/ViskyG/process-hud`. Эта инструкция находится в `docs/INSTALL_FOR_CODEX.md` относительно корня проекта.

Если репозиторий уже клонирован, используй существующую рабочую копию; проверь ветку, незакоммиченные изменения и фактическое содержимое файлов перед установкой. **Не очищай и не перезаписывай** рабочую копию. Если исходников нет, клонируй репозиторий в отдельный каталог с имеющимся доступом GitHub:

```bash
git clone https://github.com/ViskyG/process-hud.git
cd process-hud
```

Если репозиторий закрытый и доступ не настроен, объясни это пользователю и попроси путь к уже клонированной копии или разрешённый способ доступа; не используй неизвестный архив или альтернативный источник.

Проверь, что это Linux с Python 3.10+ и работающим `python3 -m venv`. Проверь наличие GUI-сеанса и способ запуска Codex: расширение VS Code или терминальный CLI. На неподходящей системе не пытайся имитировать успешную установку. Для подключения моста VS Code нужны Linux x86_64, стандартная установка VS Code и активное расширение `openai.chatgpt`.

Прежде чем что-либо устанавливать, проверь общую установку пользователя: `~/.local/bin/process-hud`, результат `~/.local/bin/process-hud doctor`, наличие `~/.agents/skills/process-hud/SKILL.md`. Если всё уже установлено, **не переустанавливай HUD только потому, что это другой диалог или агент**: переходи к проверке интеграции и использованию. Если требуется обновление или восстановление, выясни, нет ли активных задач/наблюдателей. Штатный установщик откажется обновлять работающие компоненты. Не останавливай чужие процессы и не обходи эту защиту.

### 2. Установи программу и skill, только если они отсутствуют

Если проверка существующей установки на шаге 1 успешна, пропусти установку и **не перезаписывай** общий skill. Иначе из корня репозитория:

```bash
bash install.sh
~/.local/bin/process-hud doctor
```

Установщик создаёт отдельное окружение Python, команду `~/.local/bin/process-hud` и копирует skill в `~/.agents/skills/process-hud`. Если одноимённый skill уже существовал, установщик сохраняет его резервную копию. Автозапуск задач не включается.

Убедись, что `doctor` завершается успешно и файл `~/.agents/skills/process-hud/SKILL.md` существует. Прочитай этот skill: он описывает, какие команды стоит передавать HUD, почему нельзя использовать собственные циклы `sleep`/повторных `report`, как прочитать итог и убрать обработанную строку. После установки нового skill может потребоваться перезапустить клиент Codex, чтобы он обнаружил инструкцию.

`doctor` печатает диагностику: нулевой код выхода сам по себе не подтверждает работу окна или callback. Для GUI нужны `pyside6: true` и реальное открытие окна в графическом сеансе. Отсутствие необязательного `kubectl` не мешает локальным задачам. Если `process-hud` не находится через `PATH`, используй `~/.local/bin/process-hud` во всех командах ниже.

Пути ниже относятся к стандартной установке. Настройщик моста VS Code пока требует `~/.local/share/process-hud` и стандартные каталоги VS Code; иной корень установки или другой `XDG_DATA_HOME` им не поддерживается.

### 3. При первом использовании подключи автоматический возврат

**Codex в VS Code, Linux x86_64:** перед первой длительной командой, где нужно автоматическое продолжение, проверь, есть ли мост **для текущего диалога**:

```bash
~/.local/share/process-hud/venv/bin/python -c 'from process_hud.codex_bridge import current_origin; print(current_origin()["thread_id"])'
```

Успех означает, что диалог уже обслуживается мостом. **Никакой ручной привязки агента, проекта или идентификатора диалога не требуется.** Не переустанавливай интеграцию. Если проверка не прошла, один раз выполни штатный настройщик из установленной программы:

```bash
~/.local/share/process-hud/venv/bin/python ~/.local/share/process-hud/scripts/install_codex_bridge.py --ensure
```

Если этой копии скрипта нет (старая установка), используй исходники репозитория, предварительно проверив безопасное обновление. Настройщик сохраняет резервные копии в `~/.local/share/process-hud/bridge-backups/`, проверяет существующую настройку `chatgpt.cliExecutable` и не перезаписывает несовместимое пользовательское значение. Не меняй чужие настройки обходным путём.

**При первой настройке нужно однократно перезагрузить окно VS Code.** Это связано с тем, что мост должен участвовать в запуске Codex App Server: изменённая настройка не подменяет уже запущенный процесс. После перезагрузки повтори проверку `current_origin`. Учитывай, что результат настройки `already_configured` сам по себе не доказывает подключение текущего диалога. Пока живая проверка не проходит, **не запускай** `--resume-codex` и не обещай автоматическое возобновление.

Дальнейшие диалоги в настроенном VS Code обычно работают с мостом автоматически. HUD сам определяет исходный диалог и направляет событие ему (или основному агенту для субагента); вручную регистрировать каждого Codex не нужно.

**Терминальный Codex CLI:** установленный skill и обычные команды `process-hud` доступны из терминала. Однако опубликованный `scripts/install_codex_bridge.py` интегрируется именно с расширением VS Code и **не настраивает автоматический возврат в терминальный диалог**. Не запускай его как «установку CLI-моста» и не объявляй терминальный callback работающим без отдельной подтверждённой интеграции и живой проверки. Если пользователь просит именно автоматическое пробуждение CLI, сообщи об этом ограничении и согласуй отдельное внедрение; не выдавай ручное чтение результата за автоматическое.

### 4. Проверь работу

Для базовой установки:

```bash
~/.local/bin/process-hud ui show
~/.local/bin/process-hud run --title "Проверка HUD" -- \
  ~/.local/share/process-hud/venv/bin/python \
  ~/.local/share/process-hud/examples/demo.py
```

Убедись, что команда возвращает ID, задача действительно появляется в панели, а после завершения есть отчёт и логи. Если нет графического сеанса, явно отметь, что проверена лишь работа без GUI. Не превращай проверку в постоянный опрос моделью.

**Полную проверку автоматического продолжения** проводи из реального подключённого диалога Codex после успешной проверки `current_origin` (и перезагрузки VS Code, если мост только что настроен), с разрешением пользователя. Подходящий пример успеха:

```bash
process-hud run --title "HUD — успешное завершение" --resume-codex -- \
  ~/.local/share/process-hud/venv/bin/python \
  ~/.local/share/process-hud/examples/demo.py --seconds 5
```

После запуска **заверши ожидающий ход**. Не используй `sleep`, `tail -f` и повторные проверки `report` самим агентом. Мост должен инициировать продолжение исходного диалога. В возобновлённом ходе прочитай отчёт один раз, проверь итог и убери обработанную запись.

Отдельно проверь доставку ошибки (команда специально завершится с ненулевым кодом):

```bash
process-hud run --title "HUD — проверка ошибки" --resume-codex -- \
  ~/.local/share/process-hud/venv/bin/python \
  ~/.local/share/process-hud/examples/demo.py --seconds 5 --fail
```

Агент должен возобновиться и при ошибке, сообщить её код и обработать результат, **не запуская задачу заново**. Если `--resume-codex` не видит активного моста или исходный диалог не возобновился, зафиксируй это как непрошедшую проверку. Никаких заявлений «всё работает» по одному только успешному выводу установщика.

### 5. Сообщи результат пользователю

Кратко укажи: где находится **общая установка пользователя** и использовал ли ты существующую установку; найден ли skill; какой клиент Codex настроен; включён ли мост и нужно ли перезагрузить VS Code; как прошли обычный запуск, автоматический успех и автоматическая ошибка; что осталось неподтверждённым. Покажи конкретные ошибки, но не публикуй персональные пути к чужим проектам, токены и содержимое приватных логов.

**Не меняй** конфигурацию других агентов, не включай автозапуск и не перезапускай долгие пользовательские задачи без отдельного запроса. Удаление строки из HUD не должно останавливать процесс. Если установка прервалась, изучи диагностическое сообщение и сохрани резервные копии.

## Если человек устанавливает сам

Команды для Linux из обычного терминала (из каталога, куда разрешено клонировать исходники):

```bash
git clone https://github.com/ViskyG/process-hud.git
cd process-hud
bash install.sh
~/.local/bin/process-hud doctor
```

**Мост не обязательно настраивать вручную:** установленный skill проверит и при необходимости подключит его перед первым использованием с автоматическим продолжением. Если хотите сделать это самостоятельно, выполните:

```bash
~/.local/share/process-hud/venv/bin/python ~/.local/share/process-hud/scripts/install_codex_bridge.py --ensure
```

При первоначальной настройке перезагрузите окно VS Code. В диалоге Codex попросите использовать `$process-hud` для длительных неинтерактивных команд и не опрашивать их самостоятельно. Для гарантии автоматического возврата проверьте `--resume-codex` из настоящего диалога по шагу 4 выше.

**Если работаете с терминальным Codex**, обычная установка добавляет skill и CLI для отслеживания задач; опубликованный установщик моста не подключает автоматическое возобновление терминального диалога.

Дополнительные сведения: [управление задачами](USAGE.md), [интеграция и откат моста VS Code](CODEX_BRIDGE.md), [подтверждённые испытания](VALIDATION.md). Настройки и резервные копии моста нужно откатывать по [отдельной инструкции](CODEX_BRIDGE.md#отключить-мост), прежде чем удалять программу.
